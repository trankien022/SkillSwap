# Payment outcome consumer — implementation slices

12 October 2026. Refines Phase C of payment-boundary-review.md and Accepted ADR-032 before implementation. Only confirmed FR-007/009, existing booking.confirmed/booking.cancelled/wallet.transaction.completed families and seven schemas are in scope.

1. **C1 canonical contracts** (committed d4c5e2e): legacy request discriminator, correlated durable successful wallet outcome. Supervisor contracts build/lint and 143 tests passed; schema evidence alone is not financial acceptance.
2. **C2 wallet producer — implemented**: same wallet transaction owns debit/split and successful outcome outbox. Ledger identity/time survive replay; booking advisory lock also used by refunds; final settled event cannot debit again. Focused wallet tests pass. Persisted concurrent rollback/race probes remain open. Separate meaningful commit.
3. **C3a confirmation request**: owner/expiry guard remains under database clock; eligible request keeps Pending and emits settled=false. Explicit retries remain allowed, financial dedup resides in wallet. Separate meaningful commit; funded E2E expectation must later await the outcome rather than synchronous HTTP confirmation.
4. **C3b final outcome consumer — implemented**: new pure incoming/outgoing ports and use case, a live-class persistence adapter and module registration consume only booking_payment/debit. Under the local transaction, validate stored learner/price; lock class and booking consistently, and confirm only eligible unexpired Pending with an active class. Final state and settled=true outbox share that transaction. Duplicate durable transaction IDs use a namespaced logical receipt in existing live_class.processed_events, distinct from generic bus envelope receipts; no new schema/table. Focused unit tests cover confirmation, mismatch, duplicate, expired/cancelled compensation, ignored terminal states and outbox rollback behavior. PostgreSQL rollback and restart proofs are still open.
5. **C3b compensation**: expired/cancelled pending holds never gain room access. Preserve cancellation reason and emit existing booking.cancelled compensation after late debit; original earlier cancellation cannot suppress this later request. One logical wallet outcome produces one compensation; wallet ledger unique refund remains final financial dedup. Existing confirmed/completed/no-show bookings must not be refunded merely because a delivery is duplicated. Account/amount mismatches fail without changing booking or emitting effects.
6. **C3c persisted acceptance — partial**: funded HTTP/broker test waits for Confirmed after wallet outcome; insufficient funds stays Pending with no debit or settled event, and becomes Confirmed after funding and retry. E2E also covers expired holds, late no-show refund, and exact final-event count. Full E2E passes 10/10 suites and 29/29 tests with `--forceExit`; the harness otherwise leaves an open handle after the summary. Replay/concurrency, late-expiry race, cancellation-before-debit, restart/different-envelope duplicate remain open. No claim that module transactions are a single SQL transaction; retain ADR-032's SRS discrepancy.
7. **D mobile and consumers**: processing and bounded read reconciliation until authoritative state/debit evidence; request-phase messages must never trigger confirmed push/reminders. Review notification consumers when added. Native funded/insufficient/retry evidence, graphify update and repository-wide pnpm verify before T09 closes.

Each source slice receives its own meaningful commit after supervisor review and targeted checks. Do not mark T09 done while later slices or device acceptance remain incomplete.
